## C. Configuration change during production — disclosed exception

- The owner updated the private governing documents **while the Submission run was active**. The revisions removed recurring model/concurrency confirmation questions and introduced standing owner configuration defaults.
- Their modified times preceded the **final** externally confirmed send, but the Submission Agent did not detect and reload the updated documents until **after** that send during the closing reconciliation.
- The agent reported that the compared changes did **not** alter package selection, recipient eligibility or dispatch limits; no incorrect send was established from the available logs.
- This remains a **control weakness**: start-of-run verification and closing verification do not guarantee that an in-flight sender sees a governance revision **before** its next outward action.

**Proposed, not implemented or tested:** publish a configuration revision/immutable run snapshot, prohibit live document amendments while an attempt is active where possible, and revalidate a changed revision before any next send. A central change gate or session lease is preferable to relying on model-visible prose alone.
